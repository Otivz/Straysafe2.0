# Evidence and reporting

## Evidence hierarchy

Prefer direct evidence: relevant code lines, configuration, tests, reproducible command output, build artifacts, and authorized platform settings. Label deductions as inference and state what would confirm them.

Each finding should contain:

- control or practice reviewed;
- status and severity or priority;
- precise evidence location;
- impact in this project;
- remediation and responsible owner;
- verification step;
- limitations or assumptions.

Do not paste credentials or sensitive payloads. Quote only the minimum code needed to support the finding. If line numbers are unstable, include a symbol, key, or command that allows rediscovery.

In learning mode, add a short “why this matters” explanation and one concrete example. Do not require the user to repeat answers back as a condition for completing the review.
