# Project Governance

Use this area to keep current scope, decisions, delivery status, and ownership separate from proposals and historical records.

| Documentation ID | Record | Purpose | Evidence question |
|---|---|---|---|
| DOC-02-01 | Current scope | Prevents future ideas from being mistaken for commitments. | Are included outcomes, exclusions, and success criteria explicit? |
| DOC-02-02 | Requirements | Connects implementation to accepted needs. | Can each active requirement be traced to an owner and validation method? |
| DOC-02-03 | Decision records | Preserves context that code cannot explain. | Do material decisions record context, choice, alternatives, and consequences? |
| DOC-02-04 | Delivery status | Gives readers one current project view. | Is the status dated, owned, and separated from historical updates? |
| DOC-02-05 | Risk register | Keeps known uncertainty visible. | Are significant delivery risks assigned an owner and response? |
| DOC-02-06 | Change history | Explains meaningful changes without duplicating Git history. | Are user-visible and operational changes summarized by release? |
| DOC-02-07 | Authority map | Prevents conflicting sources of truth. | Is the authoritative document identified for each major project concern? |
