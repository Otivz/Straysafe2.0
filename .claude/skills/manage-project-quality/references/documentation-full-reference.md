# Documentation Governance Reference

This index routes documentation work to the smallest relevant area. The seven area files are canonical. Project-specific records are created from templates and checked against `.agent-docs/config.json`.

## Governance contract

- Identify one authoritative source for each important concern.
- Record owner, status, last review date, and review due date when metadata is required.
- Separate current facts and commitments from proposals and archives.
- Link claims to repository or operational evidence instead of assuming completeness.
- Prefer concise navigation and focused documents over one unbounded handbook.
- Treat generated reports as evidence containers, not proof that checks passed.

## Area index

1. System documentation
2. Project governance
3. Development records
4. Testing and evidence
5. Operations and runbooks
6. Future proposals
7. Archive governance

Run `agent-docs list documentation` to discover selectors. Use `agent-docs audit documentation --strict` to check the configured project record.
