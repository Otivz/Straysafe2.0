## Intent

Give residents a mobile-first interface for the whole journey from Welcome to Logout: report an animal concern, report a lost pet or a found animal, report sightings, follow reports, claim a found animal, register pets, read community notices and manage the account. It has to run without a backend or database, so it is a self-contained, development-only module on sample data, built on the Admin preview's design tokens, with one seam for authentication and one for data so it can be reconnected later.

## Key changes

- **New module `frontend/src/resident/`**, mounted by one edit to `frontend/src/main.tsx` at `/resident-preview/*`, outside the legacy `<App />`. Nothing in the legacy portals (`/login`, `/resident-home`, `/resident/*`, `/admin`, `/staff`, `/brgy`) or the Admin preview (`/admin-preview`) was changed, moved or deleted. The legacy session guard, theme sync and API calls never run for the new routes.
- **All 40 screens (R01–R40)**, grouped by where they live:

- **Navigation:** exactly five bottom-nav destinations (Home, Community, Report, My reports, Profile), shown only on those five screens. Every other screen is a focused task with a Back button, a sticky action bar and no bottom bar.
- **Report submission is not publication.** General concerns (nuisance, safety, injured, other) are private and can never appear in Community, because the feed is built only from published, active notices. A lost-pet report publishes a notice only after the resident sees a preview of it and confirms. A found-animal report stays private ("awaiting review") until an administrator publishes it. Safety advisories are administrator-only content that residents can read. Closing a case (pet recovered, or an administrator records an outcome) removes its notice from Community. No screen shows reporter identities, administrator notes or exact addresses; notices show a general area only. There is no anonymous-posting feature, and the Register, Privacy and Help screens say that administrators can see who sent a report.
- **Text that neighbours will read** (lost and found descriptions, the place name, sightings) is checked for phone numbers, emails and exact lot addresses with the same patterns the Admin notice editor uses. A private report may contain them, because only administrators read it.
- **Statuses:** the same four global case statuses as the Admin UI (Reported, Under review, In progress, Closed). Ownership claims have their own states (Submitted, Under review, More information requested, Approved, Not approved) and never become case statuses.
- **Design system:** the Admin tokens (`admin/styles/tokens.css`, official palette verbatim), Inter, and resident-specific `rs-*` classes in `styles/resident.css` in the CSS `components` layer. 16 px inputs (no iOS zoom), 44–48 px targets, sticky top and bottom bars, safe-area insets, a centred column of at most 520 px on tablets and desktops, native `<dialog>` bottom sheets, reduced-motion support, light only.
- **Interactions with visible results:** a submitted report appears in My reports and on Home; a registered pet appears in My pets; a claim appears in My reports and its own status screen; a sighting appears in the sighting history and in the report's timeline; confirming recovery closes the report and removes the notice; profile and settings edits show immediately; notifications have read and unread states.
- **Isolation seams (reconnect points):** `auth/gateway.ts` (interface plus the preview implementation; lists the `/auth/*` endpoints it maps to) and `data/DataProvider.tsx` with `data/reducer.ts` (every change is one async action, so each maps to one request; drafts are local-only). Sample data lives only in `data/seed.ts`, generated relative to "now".
- **Preview tools** (bar at the top of every screen, "Tools"): simulate the administrator (move my latest report forward, step or decline my ownership claim, a neighbour sees my lost pet), network unavailable, fail the next save, expire the session, reload (loading and error states) and reset the sample data. They stand in for people and systems this preview does not have.
- **UI states:** loading skeleton, empty and no-match states, field validation with focus moved to the first problem, success states, inline submission errors, confirmations, unsaved-changes guard (Back, Cancel, links, tab close), session-expired sheet that cannot be dismissed, network-unavailable banner and Try again, location permission denied / unavailable / outside the subdivision, map tiles failing (typed place name still works), media type, size and count errors.
- **Dev-only gate:** `main.tsx` mounts the module behind `import.meta.env.DEV` written inline (same technique as the Admin preview), so `vite build` removes the route and the whole chunk. There is no production switch and no authentication bypass. The sample sign-in is a clearly labelled development entry on the Welcome and Sign-in screens.

## How to run

```
cd frontend
npm run dev          # then open http://localhost:5173/resident-preview/welcome
```

Use "Use the sample resident" (or the sample credentials shown on the Sign-in screen; they are fake and exist only in development builds), or create an account (verification code `123456`) to see the empty states. `npm run dev:https` works the same way.

## Dependencies on the Admin preview

The module reuses `frontend/src/admin/styles/tokens.css` and a few helpers from `frontend/src/admin/lib/` (`format`, `errors`, `previewFlags`, `hooks`, `cx`), plus the shared `frontend/src/utils/passwordPolicy.ts`. It does not touch any Admin file. If the Admin preview is retired first, move those files to a shared folder in the same change.

## Reconnecting to the backend later (genuine remaining dependencies)

1. **Authentication:** implement `ResidentGateway` in `auth/gateway.ts` with `frontend/src/utils/api.ts` (`/auth/login`, `/auth/register` then a verification step, `/auth/verify-otp`, `/auth/forgot-password`, `/auth/reset-password`, `/auth/change-password`, `/auth/verify-session`, `/auth/logout`) and delete the preview gateway. A 401 must become the `session` error kind so the expired-session sheet appears.
2. **Data:** load `ResidentState` from the API and make `dispatch` send one request per action before applying it. Endpoints the backend still needs for this UI: resident-visible report updates and outcomes, found and lost notices with sightings, ownership claims with their own states, pet registry, notifications with read state, notification preferences, a contact-message endpoint, and media upload with the limits the UI shows (photos 10 MB, videos 50 MB, up to 5 files on a report).
3. **Server-side rules the UI only mirrors:** publication policy (a private report must never be returned by the community feed), validation of public text (the form check is a courtesy), never returning reporter identities or administrator notes to residents, and ownership decisions made only by administrators.
4. **Cutover:** change `RESIDENT_BASE` and the `import.meta.env.DEV` guard in `main.tsx`, and retire the superseded legacy resident routes in `routes/AppRoutes.tsx` in the same change.

## Known limitations

- White text on the exact brand fill `#C65A17` is 4.31:1, just under AA for small text. Filled buttons therefore use the derived `#A94A12` (5.7:1); the exact brand orange is used for icons, bars and the active indicator.
- All data is sample data kept in the browser tab (`sessionStorage`); nothing is persisted or shared, and photos are object URLs that do not survive a reload. Signing in as a different account replaces the stored sample state.
- The browser Back button is not intercepted by the unsaved-changes guard (`<BrowserRouter>` cannot block navigation); Back, Cancel, in-page links and closing the tab are.
- Map tiles come from OpenStreetMap, as in the legacy portals. If they cannot load, the picker keeps working with a typed place name.
- The office name, phone, email and hours are sample information, labelled as such on screen.
- The sample credential and the verification code in the preview are fake development values, excluded from production builds. They are not secrets.
