## Intent

Before the first APK build, let the developer point the installed debug app at a backend on their own Wi-Fi (`http://192.168.1.10:8000`) or at an HTTPS tunnel, and change it later, without a new GitHub build. Release-style Android builds keep one fixed HTTPS address and must not contain any of it.

## Supersedes (part of the earlier record, which is not edited)

`2026-11-09_1547_android-resident-app.md` described a build-time cleartext switch (`STRAYSAFE_ALLOW_CLEARTEXT`, the workflow input `allow_http`, `-PallowCleartext`, a manifest placeholder). That is replaced here: the workflow has no inputs; plain-http is allowed only by the Android **debug build type**; a build-time address is always HTTPS; `frontend/android/app/build.gradle` is back to its original content. Everything else in that record stands.

## Key changes

- **Two Android modes.** `vite build --mode android-debug` (new; what the workflow builds) is the Resident-only Android app plus Connection Settings; `--mode android` is unchanged in purpose (Resident only, fixed HTTPS address required) and now contains none of the debug code. `package.json` gets `build:android:debug`; `main.tsx` treats both as the Android app (Resident only, `/` redirects to `/resident-app`).
- **Connection Settings** (`src/resident/devConnection/`): screen with the address field, Test connection, Save & connect, Save anyway (after a failed check), the current connection and its live status, and the note that `localhost`/`127.0.0.1` on a phone mean the phone itself. Entry points: the "Debug build · address · Connection" bar on every screen (the existing `Banner` slot of the Resident mode), Settings → Developer, and the first launch when no address is saved or built in (the app then makes no request until one is saved). Wired through one optional `devConnection` field of `ResidentMode`, which is undefined in every other build, so the shared screens never import it.
- **Address logic** (`src/utils/devBackend.ts`, pure): normalization and validation (LAN http, https tunnel, bare-IP and bare-name shorthand; refuses loopback, plain http to a public host, other schemes, credentials, `?`/`#`), a read-only test (`GET /`, no cookies, no credentials, 8 s limit, four failure kinds), the saved address (same `straysafe_server_url` key as the older Server settings; re-validated on every read), and `switchBackend` (sign out locally, remove everything stored in `localStorage` and `sessionStorage` except the new address, reload, sign in again). No backend change: the existing root route is the health check.
- **One address everywhere.** `src/utils/api.ts` takes the saved address (debug mode only), else the optional built-in one, else none; the shared `api` client, the sign-in/OTP calls, token refresh, sign-out, push and avatars all read `API_BASE_URL`. No second client and no fallback to another server.
- **Build guard** (`scripts/androidApiUrl.ts`, `vite.config.ts`): a built-in address is HTTPS-only in both modes; the debug mode may have none. The `allowCleartext` argument is gone.
- **Native networking.** The main manifest no longer sets cleartext (Android's default for API 28+ is HTTPS only); `android/app/src/debug/AndroidManifest.xml` sets `usesCleartextTraffic="true"` for the debug build type only. `capacitor.config.ts` serves the page as `http://localhost` when `STRAYSAFE_ANDROID_DEBUG=true` (so it may call an http LAN address without mixed-content blocking), otherwise `https://localhost`. No network security configuration, no custom trust, no certificate exceptions.
- **Workflow.** Still manual, debug APK, same artifact. The `allow_http` input and `-PallowCleartext` are removed; `STRAYSAFE_ANDROID_DEBUG=true`; `VITE_API_BASE_URL` is optional (HTTPS only if set); builds with `build:android:debug`; two new guards fail the run if the Connection Settings chunk is missing or the page is not `http://localhost`.
- **A lesson kept in the code:** the bundler (Vite 8) folds a build-mode constant only within one module. A first version exported the flag from a shared file and leaked a `ConnectionPage` chunk into the release-style bundle; the flags are now defined in the file that uses them, with a comment saying why. This also kept `main.tsx`'s exclusion of the Admin and preview chunks as strong as before.

## Not verified, blockers

1. **No APK has been built.** `MainActivity.java` (previous record) and the debug manifest overlay have not been compiled or merged by Gradle; the runner's Android SDK must include platform 36.
2. **Nothing was tried on a phone:** typing and tapping on Connection Settings, the confirmation and reload, a real LAN request and a real tunnel request from the web view, certificate behaviour, and everything listed in the earlier record.
3. A tunnel that shows a warning page to browser requests (some free ngrok plans) is reported as "Not the StraySafe API"; use a tunnel without it.
4. The debug APK can be pointed at any reachable backend: it is for developers only. A release workflow (keystore, `build:android`, no debug flag, `assembleRelease`) does not exist yet.
5. The test uses the existing root route as the health check. If it is ever changed from the `Welcome to StraySafe API` greeting, `testBackend` and its tests must change with it.
