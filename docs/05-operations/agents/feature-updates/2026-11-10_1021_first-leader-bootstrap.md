## Intent

The [clean database rebuild](2026-11-10_0915_clean-database-rebuild.md) left the local database with no user, and the application can create a Subdivision Leader only through an Admin (role 4 is reserved and none exists). Give the developer a first Leader to sign in with, without seeding an Admin or a default credential and without adding an account-management workflow to the application.

## Key changes

- **A local bootstrap tool, outside the repository.** `C:\StraySafe-db-backups\tools\bootstrap_first_leader.py` asks for the Leader's name, e-mail address, optional phone number and position and a password (typed twice, never shown), checks the password with the application's own policy, hashes it with the application's own bcrypt helper and inserts exactly one `users` row through the application's own `User` model: role 2, linked to the existing subdivision, Active, verified, not a head officer. It refuses to run outside a real local terminal, against any database other than `straysafe_subdivision` on this computer, when a Leader already exists, or for a duplicate e-mail address, phone number or name. It writes nothing else and no file, and never prints or stores the password, the hash or the connection settings. The details are in the last section of the database document.
- **The account.** The developer ran the tool in their own terminal and typed the details and the password themselves; the AI never saw, printed or stored the password, and the database holds only its bcrypt hash. Result: one role-2 account (user id 1) linked to subdivision 1 (Selera Homes).
- **Documentation.** `DATABASE_FILES_AND_MIGRATIONS.md`: a new last section, a corrected status line and "Account provisioning" bullet, and "before the first Leader was added" on the rebuild's verification bullet. `overview.md`: the role 4 row now says the first Leader of the local database was created by the local script. `README.md`: an index row for this record, and the earlier record's row now says its open decision was resolved by this one.
- **Not changed.** The schema, the reference data, every other table, the backend, the frontend, the tests, `.env`, the backup and the clean init file. No Admin or Barangay account exists. The repository snapshot `Database3.4_subdivision.sql` still contains the old demo accounts with their default password hash, and `backend/scripts/seed_admin.py` still seeds demo accounts with a built-in default password when it is run; this work used and changed neither, and the operations README and the defence plan still point to those seed accounts.
