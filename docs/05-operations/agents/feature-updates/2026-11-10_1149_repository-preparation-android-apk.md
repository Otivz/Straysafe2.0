## Intent

Make the repository safe to push to GitHub and to build the first Android APK from: no hardcoded demo credentials, fallback passwords, demo identities or user seeds in the files the request names, documentation that no longer recommends them or the old database initialization, and a check that the Android build inputs are complete and consistent.

## Key changes

- **`seed_admin.py` rewritten.** The old script seeded a Citizen, three more Residents, a Subdivision Leader, a Barangay Staff and an Admin, with real-looking personal e-mail addresses, names, home addresses and avatar URLs, and used a built-in default password whenever `SEED_PASSWORD` or `ADMIN_PASSWORD` was not set. On every run it also overwrote existing users' details, reset the Admin's password, and overwrote report category names with stale ones (category 4 "Roaming Animal" would have become "Roaming"). The new script contains no account, e-mail address, name or password and has no default for any setting; it seeds no reference data and creates no table. It creates nothing unless asked: `--leader` (from `SUBD_LEADER_EMAIL` and `SEED_PASSWORD`) or `--admin` (from `ADMIN_EMAIL` and `ADMIN_PASSWORD`; the role is reserved). A password must meet the application's policy and may not be the `.env.example` placeholder; every requested account is checked before anything is written; an existing account is left exactly as it is; the Barangay Staff role is not created; a database error is reported without parameters, hashes or passwords.
- **`run_admin_readiness_audit.py`.** It signed in with the old default Admin e-mail address and password. It now reads `ADMIN_EMAIL` and `ADMIN_PASSWORD` from the environment or `.env` and stops with a message when they are missing. It was not run.
- **`Database3.4_subdivision.sql` and its `.txt`.** The seed rows of `users`, `notifications` and `audit_logs` are removed and `coverage_settings.updated_by` is `NULL`. This is the same transformation that produced the clean initialization the local database was rebuilt from, and the two files have the same executable SQL. The schema (51 tables) and the nine reference tables (55 rows) are unchanged. A revision note at the top of the file records the change. The `.txt` is a byte-for-byte copy.
- **Documentation.** `setup.md` (the database step loads `Database3.4_subdivision.sql`, the `.env` step points to `.env.example`, "Seed Test Accounts" is replaced by "First accounts"), `tunnel.md` (the seed account table replaced), `docs/05-operations/README.md` (two statements), `LOCAL_NETWORK_IP_AND_APK_SETUP_GUIDE.md` and `DEFENSE_PLAN.md` (one line each), `docs/02-project/README.md` (the resolved `setup.md` row removed), `DATABASE_FILES_AND_MIGRATIONS.md` (file table rows, a corrected bullet and a new last section) and the index.
- **Android build review: nothing needed changing.** No concrete blocker was found in the workflow, the Capacitor configuration or the debug Connection Settings, so no Android, workflow or frontend file was edited.
- **Left as it was, for the developer to decide.** The older snapshots `Database3.3.txt` and `Database3.3_subdivision.sql` still seed the demo accounts. One `landmarks` seed row (the Temporary Holding Pen) still names the removed demo Leader and a phone number as its contact; it is reference data, and changing it would make the snapshot differ from the rebuilt local database. Git history before this change still holds the old demo data and was not rewritten. `.env.example` keeps its placeholder values (agents do not edit `.env*` files). Two tests use the old default as a password that must be rejected, and a few interface fallbacks show `admin@straysafe.com` as a placeholder; neither is a credential.
