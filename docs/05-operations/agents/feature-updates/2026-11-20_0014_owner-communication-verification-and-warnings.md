## What changed and why

1. **Message Owner & Send Warning Actions (`PossibleOwnersBlock.tsx`, `RegisteredPetPanel.tsx`):**
   - Added **Message Owner** and **Send Warning** actions alongside registered pet owner details in both the **Possible Pet Owners** and **Registered Pet Owner** sections on Subdivision Admin Case Details pages (`CaseDetailPage.tsx`, `MonitoredCasePage.tsx`).
   - Displayed Owner's name, Registered pet's name, Pet species, Breed, Recorded colours, Contact information (authorized admin view), and Case reference (`SS-YYYY-NNNN`), hiding actions when no valid owner account is linked.
2. **Ownership Verification Workflow & Status Lifecycle (`owner_verification.py`, `manual_matching.py`, `OwnershipVerificationCard.tsx`):**
   - Added predefined **Ownership Verification** and **General Inquiry / Direct Message** modes in `POST /owner-verification/reports/{report_id}/message` with the standardized default verification prompt.
   - Updated the Resident Inbox verification card buttons to **Confirm Ownership** and **Decline Ownership**.
   - Confirming sets the request status to **Owner Confirmed – Pending Administrator Verification** and `report.ownership_status = "under_review"` without auto-finalizing ownership, and notifies all active subdivision leaders (`type="owner_verification_response"`).
   - Declining sets the request status to **Ownership Not Confirmed** and `report.ownership_status = "unconfirmed"`, records case history, and notifies subdivision leaders.
   - Authorized Subdivision Admins finalize ownership via **Confirm Ownership (Finalize)** (`POST /owner-verification/requests/{request_id}/verify`), setting `report.ownership_status = "confirmed"`, `report.identity_status = "identified"`, and `report.pet_id = req.pet_id`.
3. **Message Delivery & Read Status (`case_messaging.py`, `MessageThread.tsx`, `ConversationPage.tsx`):**
   - Added `last_delivered_message_id` to `CaseMessageMember` and implemented `Sent` -> `Delivered` (when fetched by the recipient via `summary` or `view`) -> `Read` (when opened/acknowledged via `mark_read`, logging `CASE_MESSAGE_READ`) status indicators on outgoing chat messages.
4. **Official Warning Management, Resident Delivery, Acknowledgment & Response (`warnings.py`, `ActionsTab.tsx`, `WarningLetterPage.tsx`, `CaseDetailPage.tsx`):**
   - Extended `OwnerWarning` with `warning_category`, `warning_subject`, `additional_details`, `supporting_documents`, `admin_notes`, `workflow_status`, `owner_response`, `owner_responded_at`, `thread_id`, and `client_request_id` (with idempotent duplicate protection and startup schema helper `ensure_owner_communication_and_warning_columns`).
   - Built `SendOwnerWarningDialog` with auto-populated Owner, Pet, Case Reference, Warning Category, Warning Subject, Warning Message, Date Issued, Additional Details, Supporting Documents upload, Administrative Notes, and a **Preview & Confirmation** step before sending.
   - Issuing a warning creates the `OwnerWarning` and immutable `GeneratedWarningLetter`, delivers the official warning to the owner's Resident account (`/resident-app/warnings/{letter_id}`), posts the warning notice into the owner's 1-to-1 Resident Inbox conversation (`/resident-app/conversations/{thread_id}`), and dispatches an in-app notification (`type="warning_letter"`).
   - Updated Resident `WarningLetterPage.tsx` with **Acknowledge Receipt** (confirming receipt only without admitting fault or closing the warning, notifying subdivision leaders via `type="warning_acknowledged"`) and a **Response or Clarification** form (`POST /warnings/{warning_id}/respond`, updating `workflow_status = "Responded"`, posting into the linked conversation, logging history/audit, and notifying subdivision leaders via `type="warning_responded"`).
   - Added a dedicated **Warnings** section (`CaseWarningsSection`) and tab on Subdivision Admin Case Details displaying all warning attributes, owner acknowledgment, and owner response, with admin status updates, internal notes, and follow-up message delivery (`POST /warnings/{warning_id}/admin-update`).
5. **Verification:**
