## Intent

The Android app can receive the Leader's alerts and every other notification on the lock screen once the developer has done the Firebase steps, and the build keeps working without them.

## Key changes

- **Dependency:** `@capacitor/push-notifications` 8.1.3 (Capacitor 8), installed with npm 10.9.3 (the build runner's npm) and `--ignore-scripts`: the lockfile gains the package and flips `peer` flags only (no version or integrity changes).
- **App:** after sign-in it creates the channels "Updates on your reports" (private on a locked screen) and "Lost & found alerts" (public), asks for permission (Android 13+), registers and sends its token to `/push/subscribe` (`channel: "fcm"`; a 503 while Firebase is not set up is ignored); a tap opens `data.url` (paths inside the app only); signing out removes the phone first (`/push/unsubscribe`, never holding the sign-out more than 2.5 s). Nothing runs in a browser.
- **Android:** `POST_NOTIFICATIONS`, the default notification icon (a white paw), colour and channel; notifications show while the app is open (`presentationOptions`). Plugin wiring comes from the runner's `npx cap sync android` (a local `cap update` needs built web assets).
- **Build:** a workflow step writes `google-services.json` from the repository secret `GOOGLE_SERVICES_JSON` after checking it is for `com.straysafe.app`, and builds without push when the secret is absent. `.gitignore` covers `google-services.json`, `GoogleService-Info.plist`, `*firebase-adminsdk*.json` and `*service-account*.json` (no tracked file matches).
- **Docs:** the developer's console-only steps in `FIREBASE_PUSH_SETUP.md` (the service-account key stays outside the repository, named by `FCM_SERVICE_ACCOUNT_FILE`).
